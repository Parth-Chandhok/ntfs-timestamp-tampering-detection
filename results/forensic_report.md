## Incident summary

Out of 1308 files analysed on the NTFS volume, the engine flagged 704 as tampered, leaving 604 as benign with no false positives. Direct Standard Information modification affected 404 files, where the user-space creation timestamp was overwritten while the kernel-managed File Name attribute remained unchanged, causing the two attributes to disagree. This discrepancy was exposed because 404 files exhibited creation time disagreements between $SI and $FN. Directory relocation, or the move-trick, affected 100 files where both attributes were falsified so that the Master File Table showed no internal disagreement. This method was exposed solely by the Change Journal, which revealed that 504 files had timestamps modified after the file was closed and 504 files claimed to predate their first journal entry. System clock rollback affected 200 files created while the system clock was set backward, meaning timestamps were honestly recorded from a dishonest clock with no internal file disagreements. This method was exposed because 704 files claimed times predating the journal's running maximum, and 200 files were created inside a rolled-back clock window within the Event Log. Consequently, investigators relying on file timestamps face manipulated data where traditional attribute checks miss advanced tactics, requiring the integration of journal and event log analysis to uncover the truth.
